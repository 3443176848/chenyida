# 晨亿达 ERP 小团队 V1 试运行准备包

> 状态：`SYNTHETIC STARTER PACK / NO REAL DATA / NO UAT WRITE AUTHORIZATION / PRODUCTION NO-GO`
> 日期：2026-08-24（Asia/Shanghai）
> 业务基线：D-167、D-170

环境进度见[新建隔离UAT L1只读就绪报告](environment-readiness.md)：源码/0046基线可用，但新UAT尚未创建；当前主机因固定控制路径、过期候选镜像和磁盘硬线余量不足而保持L2 NO-GO。

## 1. 这套准备包解决什么

当前没有可用真实样本，因此先用一套完全虚构、数字可人工复算的“10件控制板”样本，把市场、工程、计划、采购、仓库、生产、品质、财务和管理串成一单到底的员工UAT。

这套准备包只定义输入、操作、预期结果和证据格式。它不会连接数据库、创建账号、部署版本、运行Migration或写入UAT/生产。

## 2. 文件

- [虚构业务样本](synthetic-sample.md)：一套可直接照录的客户、供应商、物料、产品、BOM、工艺、数量、价格和日期规则。
- [员工UAT执行与核对清单](uat-checklist.md)：按岗位列出操作、交接、预期状态、数量金额、证据和停止条件。

## 3. 最小使用方式

1. 项目负责人指定本次UAT负责人和实际参与者。人数按实际情况确定，不要求每岗2人。
2. 明确目标是独立UAT，不是当前生产；明确数据保留、清理和回退责任人。
3. 取得单独授权后，把目标UAT升级到与候选源码一致的版本并建立可恢复快照。
4. 用虚构样本逐项录入，不复制真实客户、供应商、联系人、价格、银行账号或附件。
5. 每完成一次交接，记录单据ID、版本、状态、数量金额和request_id；出现P0立即停止后续写入。
6. 最终以核对表判断`PASS / FIX_REQUIRED / BLOCKED`，不以页面打开或按钮存在判断完成。

## 4. 试运行角色

| 业务职能 | 当前角色代码 | UAT责任 |
| --- | --- | --- |
| 管理/负责人 | `manager` | 例外批准、工艺/品质异人放行、最终签收 |
| 市场/销售 | `sales` | 客户、项目、报价、订单、发货指令 |
| 工程 | `engineering` | 产品、BOM、Routing、需求解析和计划包 |
| 计划 | `planning` | 需求计算、采购申请和生产交接 |
| 采购 | `purchase` | 供应商映射、RFQ、报价、定标、PO |
| 仓库 | `warehouse` | 收货、批次、领料、完工入库和出货 |
| 生产 | `production` | 接收生产交接、工单、派工和报工 |
| 品质 | `quality` | IQC、FQC、不合格和关闭 |
| 财务 | `finance` | AP、AR、收付款和冲销 |
| 治理审核 | `operations` | Supplier Mapping异人审核；不是固定业务编制 |
| 环境准备 | `admin` | 仅限获批的UAT账号与基础配置，不参与日常业务代办 |

每名实际参与者必须使用独立账号。当前模型每账号一个角色；如一人兼岗，应先记录真实兼岗关系并确认最小权限方案，不能使用共享账号。

## 5. 开跑前必须确认的业务门

采购和投产何时可以开始，目前需要项目负责人二选一：

- `SO_REQUIRED`：正式销售订单已接受后，才允许发RFQ、转PO和发布工单。推荐作为常规订单默认门。
- `PRE_SALES_EXCEPTION`：样品、打样或备货可在销售订单前启动，但必须有负责人批准的内部授权编号、金额上限和有效期。

在该选择未记录前，只能演练到计划需求和报价，不进入采购订单或工单业务写。当前系统是否技术强制该门，应在UAT中验证，不能用人工口头约定冒充服务端控制。

## 6. 授权分层

| 层级 | 动作 | 当前是否授权 |
| --- | --- | --- |
| L0 | 编写/审阅虚构样本和清单 | 已授权 |
| L1 | 只读核对候选源码、Migration差异和目标UAT状态 | 未授权，需明确目标环境 |
| L2 | 建立UAT快照、升级候选版本、运行0041—0046、创建临时实名账号 | 未授权，需逐项批准 |
| L3 | 在独立UAT写入本包虚构样本并执行员工旅程 | 未授权，需明确参与者、时间窗和清理方式 |
| L4 | 读取或试迁移脱敏/真实业务样本 | 未授权，需数据范围与责任人批准 |
| L5 | 生产部署、真实库存/订单/财务写入或切换 | 未授权；本准备包不构成上线批准 |

“继续”“下一步”只授权当前已说明的L0文档工作，不自动扩大为L1—L5。

## 7. 通过定义

本包准备完成只表示“可以申请独立UAT环境试跑”，不表示已经试运行或可以上线。真正通过至少需要：

- 同一候选版本、同一UAT数据库完成完整员工交接；
- 关键稳定ID、状态、数量、金额和审计事实全部核对；
- 权限拒绝、幂等、CAS和合法冲销有实际证据；
- UAT前快照可恢复，测试数据可精确清理；
- P0为0，剩余问题有责任人和处理决定；
- 项目负责人明确签收UAT结果。

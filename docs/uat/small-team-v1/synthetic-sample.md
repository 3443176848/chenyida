# 小团队 V1 虚构业务样本：10件控制板

> 样本编号：`CYD-UAT-SYN-001`
> 数据等级：`SYNTHETIC ONLY`
> 适用环境：获批的独立UAT
> 禁止用途：不得作为真实客户、供应商、报价、银行账户或正式财务凭证

## 1. 场景目标

用1件采购原料生产1件成品，完整交付10件。所有名称和编号均为虚构，数量和金额故意保持简单，便于员工不依赖系统也能人工复算。

```text
采购原料10 PCS × 12 CNY = AP 120 CNY
生产领料10 PCS → 完工10 PCS
销售成品10 PCS × 20 CNY = AR 200 CNY
FQC放行10 PCS → 出货10 PCS
```

## 2. 日期规则

执行时先填写`D0`，其余日期只按偏移计算，避免把固定日期写死：

| 事实 | 日期 |
| --- | --- |
| UAT开始日 | `D0` |
| RFQ回复截止 | `D0 + 3天` |
| 供应商承诺到货 | `D0 + 10天` |
| 计划需料日 | `D0 + 12天` |
| 目标交付日 | `D0 + 20天` |
| 报价有效期 | `D0 + 30天` |

所有无时区业务日期必须原样保持`YYYY-MM-DD`，不得因服务器时区变为前一天或后一天。

## 6. 商务门和销售订单

执行采购或生产前，记录本次选择：

| 选择 | 本次值 | 证据 |
| --- | --- | --- |
| `SO_REQUIRED` | `[ ]` | 已接受销售订单ID |
| `PRE_SALES_EXCEPTION` | `[ ]` | 负责人授权编号、金额上限、有效期 |

推荐本虚构样本使用`SO_REQUIRED`。销售报价为10 PCS × 20 CNY，有效期D0+30天；状态依次为`草稿 → 发布 → 接受 → 转销售订单`，销售订单总额应为200 CNY。

如果当前产品允许在两种门都不存在时发RFQ、转PO或发布工单，登记为业务控制缺口，不得用口头同意改写为PASS。

## 9. 财务更正样本

财务对AR登记收款200 CNY，然后模拟“银行退回”：

1. 原收款事实保留；
2. 追加一条反向结算记录；
3. AR恢复`OPEN`；
4. 已结金额恢复0；
5. 同一原收款不得重复冲销。

不得删除原收款或直接把金额改成0。

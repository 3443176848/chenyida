# AI 治理评估与审批边界 V1

状态：`APPROVED / GOVERNANCE BASELINE ONLY / IMPLEMENTATION NOT STARTED`

任务：`PHASE4-TASK01`

决定：`D-110`

日期：2026-08-10

适用范围：晨亿达 ERP 物料分类、属性提取、候选匹配和供应商映射建议

## 1. 目的

本合同规定未来 AI 辅助物料治理的权限边界、证据合同、离线评估合同和人工审批责任。AI 只产生可丢弃、可追溯的建议；正式业务事实继续由既有服务端权限、确定性规则、事务、CAS、幂等、审核和审计控制。

本文件不实现或授权模型调用、API、页面、Schema、Migration、生产试点或部署，也不选择任何外部 AI 供应商。

## 2. 权威顺序

建议处理必须遵守以下优先级，低优先级结果不得覆盖高优先级结论：

1. 服务端权限、数据域和法定/合同限制。
2. 确定性冲突、客户专用、单位不兼容、冻结和生命周期门禁。
3. 当前有效的品类、属性、供应商映射和物料版本规则。
4. 人工审批结论。
5. AI 建议及其置信度。

命中前四类拒绝或阻断时，AI 输出只能被忽略、标记为冲突证据或转入 `NEEDS_REVIEW`，不能放宽门禁。

## 3. AI 能做与不能做的事

### 3.1 允许的候选输出

未来独立实施任务可以让 AI 在候选层生成：

- 品类建议及备选品类；
- 结构化属性值建议及逐字段证据；
- 可能的既有内部物料候选及差异；
- 供应商料号到内部物料的映射建议；
- 无法安全判断时的明确放弃回答结果。

这些输出不是正式物料、映射、审批或业务事实，可以被删除、替换、过期或拒绝。

### 3.2 禁止的直接动作

AI 不得直接：

- 创建、合并、启用、冻结、停用或覆盖正式物料；
- 写入 `material master`、正式属性、supplier mapping、legacy mapping；
- 写入或改变 BOM、库存、采购、生产、品质或财务业务事实；
- 生成正式内部编码或把候选身份当作正式编码；
- 批准、驳回、代签或跳过任何既有人工审批节点；
- 降低权限、CSRF、事务、CAS、幂等、并发、审核或审计要求；
- 根据人工反馈自动训练、自动调阈值、自动改 prompt、自动改规则或自动发布；
- 在没有后续独立授权时连接生产、试点、部署或调用外部模型。

## 4. 失败关闭合同

以下任一条件出现时，结果必须失败关闭为 `NEEDS_REVIEW` 或“无建议”，不得回退为猜测值：

| 条件 | 必须结果 |
| --- | --- |
| 请求超时、模型不可用或模型异常 | 无建议；记录稳定失败分类和 `request_id` |
| 缺少逐字段证据或证据无法定位 | `NEEDS_REVIEW` 或无建议 |
| 输出不符合受控 Schema、字段越界或类型非法 | 拒绝整个输出，不做部分正式写入 |
| 数据集、规则、prompt、Schema 或物料版本漂移 | 结果过期；重新评估或人工复核 |
| 置信度低于经批准阈值 | `NEEDS_REVIEW` 或放弃回答 |
| 确定性冲突、客户专用、单位不兼容、冻结或生命周期门禁 | 确定性门禁优先；AI 不得覆盖 |
| 未知品类、缺关键规格或存在歧义 | 放弃回答或给出有界候选并进入人工复核 |

低置信度的具体数值阈值不在本任务决定。阈值只能在 `PHASE4-TASK02` 用已标注样本测量后，由项目负责人批准。

## 5. 外部模型与数据边界

### 5.1 默认状态

- 外部 AI 供应商默认禁用。
- 本任务不选择供应商、模型或部署地域。
- 本任务不创建、接收或保存 API Key。
- 本任务不发送真实供应商文件、价格、个人信息、凭据、客户专用资料或生产正文。

### 5.2 未来准入前置条件

未来如需接入外部模型，必须另立任务并在调用前完成：

1. 数据分类和允许字段清单；
2. 去标识化、脱敏和最小化方案；
3. 供应商保留期、训练使用、删除和审计条款；
4. 数据处理地域和跨境边界；
5. 商务合同、保密和分包商审查；
6. 凭据创建、保管、轮换、撤销和最小权限授权；
7. 非生产隔离、停用开关、故障回退和事件响应；
8. 项目负责人对具体试点范围的独立批准。

任一项未完成时，外部模型保持禁用。

## 6. AI 建议追溯合同

未来每条 AI 建议必须拥有稳定 `suggestion_id`，并至少记录以下去敏元数据：

| 字段 | 合同 |
| --- | --- |
| `suggestion_id` | 全局稳定、不可复用的建议标识 |
| 输入摘要 | 规范化后输入的摘要，不保存未授权正文 |
| 数据集版本 | 输入参考数据集的稳定 ID、版本和摘要 |
| 规则版本 | 确定性预处理、门禁和后处理规则版本 |
| 模型身份 | provider、model ID、model version；本地规则基线应显式标识非模型 |
| prompt 身份 | prompt 模板版本和模板摘要；不在审计中保存敏感拼接正文 |
| 参数摘要 | 温度、随机种子、解码和其他影响结果的受控配置摘要 |
| 输出 Schema | Schema ID、版本和摘要 |
| 逐字段证据 | 每个建议字段的来源定位、规则/模型证据和冲突说明 |
| 置信度 | 定义明确、版本绑定的字段级和整体置信度；不得跨版本直接比较 |
| 请求标识 | `request_id`，用于关联服务端调用、失败和审计 |
| 时间 | 生成时间、过期时间或版本漂移时间 |

不得只保存最终文本、单一总分或无法重放的“模型认为相似”。无法满足追溯字段时，该建议无资格进入人工审批工作台。

## 7. 人工决定合同

人工决定必须与 AI 建议分开保存，不得用 AI 输出覆盖人工记录。未来每个决定至少绑定：

- 被审建议 ID 和建议版本；
- 当前正式对象版本或申请版本；
- 审核人稳定身份和角色；
- 决定：接受、部分接受、拒绝、要求补充或放弃；
- 逐字段采用结果和人工更正；
- 理由、证据引用和决定时间；
- `request_id`、CAS 版本和审计结果。

人工反馈只形成离线质量统计和失败样本，不得自动训练模型、自动改变阈值或自动修改生产规则。任何反馈利用方式必须形成新版本、重新评估并单独批准。

## 9. 版本化去敏评估集合同

### 9.1 身份与不可变性

每个评估集版本必须包含稳定 `dataset_id`、语义版本、创建时间、去敏策略版本、样本清单摘要和整体 SHA-256。已批准版本不可静默改写；任何样本、标签、切分或去敏规则变化都必须生成新版本和新摘要。

评估集不得包含真实价格、个人信息、凭据、客户/供应商未授权正文或可逆的直接身份。需要保留业务语义时应使用合成、替换、分桶或不可逆摘要，并记录去敏限制。

### 9.2 固定 holdout

- 评估集必须把开发/校准样本与固定 holdout 分开。
- holdout 的样本身份、标签和摘要在版本内固定。
- holdout 不得用于 prompt 编写、规则调试、阈值选择、失败样本修补或示例检索。
- 如果 holdout 泄漏、标签修订或样本被用于调优，必须封存旧版本、创建新版本并重新建立基线。

### 9.3 场景覆盖

评估集至少覆盖：

- 正例、反例和近似但非同物料样本；
- 重复、冲突、缺字段、错类型和噪声输入；
- 单位可换算与单位不兼容；
- 客户专用、冻结、停用和生命周期冲突；
- PCB/FPC/SMT 行业特殊规格及同名异物；
- 越界字段、提示注入式正文、异常长度和非法 Schema；
- 证据不足、未知品类和应放弃回答场景。

样本应按品类、来源、风险等级、缺失模式和决定类型分层统计，不能只报告总平均值。

## 10. 四类能力分别评估

| 能力 | 主要输入/输出 | 核心关注 |
| --- | --- | --- |
| 分类建议 | 去敏物料描述 → 品类候选/放弃 | 错分、未知品类、关键门禁 |
| 属性提取 | 去敏字段 → 类型化逐字段值/证据 | 字段精度、单位、缺失与幻觉值 |
| 候选匹配 | 规范化物料 → top-k 内部候选/放弃 | 正确候选召回、错误候选和冲突 |
| 供应商映射建议 | 去敏供应商身份/料号/规格 → 映射候选/放弃 | 来源真实性、规格相容和错误绑定 |

四类能力必须分别出具结果，不得用一个综合分掩盖某一高风险能力失败。

## 11. 指标合同

每次评估至少输出：

- 逐字段 precision、recall 和 F1；
- 整条记录 exact match；
- 候选匹配和映射建议的 top-k recall；
- 错误候选率；
- abstention rate、coverage 及在 coverage 范围内的准确性；
- 相同版本和固定配置下的稳定复现率；
- 关键安全违规数。

指标必须同时按能力、品类、风险场景和版本分层。缺失预测不得被统计为正确；放弃回答必须同时进入 abstention 和 coverage 口径，不能从分母静默删除。

### 11.1 零容忍门禁

以下关键安全违规允许值固定为 `0`：

- 直接写入或尝试写入正式业务事实；
- 绕过、代替或降低人工审核；
- 覆盖确定性客户专用、单位、冻结或生命周期门禁；
- 未授权外发受限数据或凭据；
- 在停用开关关闭时继续产生可消费建议。

任一关键安全违规使该版本评估失败，不得用平均准确率抵消。

### 11.2 准确率阈值

本任务不凭空设定分类、属性、匹配或映射准确率阈值。`PHASE4-TASK02`必须先在已标注样本上测量确定性基线与候选方案，再由项目负责人批准每项能力、品类和风险等级的阈值及最低 coverage。

## 12. 可复现评估记录

未来每次评估运行至少记录：

- `evaluation_run_id`、运行时间和执行环境摘要；
- 评估集 ID、版本、清单摘要和 holdout 身份；
- 规则、模型、prompt、参数和输出 Schema 版本；
- 代码或 evaluator 版本；
- 每项指标、分层结果和关键安全违规数；
- 去敏失败样本、预期标签、实际输出和证据；
- 结果制品摘要、批准/拒绝人、理由和时间。

评估结果、失败样本和批准记录必须可重复生成、可独立审阅并保留审计链。不得只保存截图或人工摘录总分。

## 13. 版本变更、漂移、停用与回退

以下任一变化都必须形成新版本并重新通过固定评估集：

- provider、model ID、模型版本或托管方式变化；
- prompt 模板、示例、系统指令或参数变化；
- 预处理、确定性规则、门禁、阈值或输出 Schema 变化；
- 参考数据集、物料分类/属性定义或候选索引版本变化。

禁止供应商“自动升级”后静默沿用旧批准。未来实现必须具备：

- 全局和按能力停用开关；
- 回退到最近已批准版本的配置；
- 版本漂移检测和结果过期标记；
- 定期及事件触发复评；
- 关键安全违规或漂移时立即停止消费建议。

停用 AI 后，确定性规则和人工流程必须仍能运行；系统不得因 AI 不可用而放宽正式写入门禁。

## 14. 发布门禁

本治理基线本身不授权试点。未来任何非生产试点至少需要：

1. `PHASE4-TASK02` 的版本化去敏评估集、确定性基线和离线 Evaluator；
2. `PHASE4-TASK03` 的关系化 Suggestion/Evidence 候选层；
3. `PHASE4-TASK04` 的人工审核 API/UI 与受控正式提交衔接；
4. `PHASE4-TASK05` 的非生产发布门禁、漂移监控、停用和回退验收；
5. 项目负责人对具体数据、模型、角色、环境和时限的独立授权。

生产试点、真实数据外发、生产模型凭据、生产迁移或部署必须另行授权，不能由五个 Phase 4 任务自动推导。
